# chrome_150 profile

Evidence for the `chrome_150` profile, which is active in the table. Everything
here is regenerated by the commands below; none of it was hand-written.

## Files

| File | What it is |
| --- | --- |
| `captures.json` | 3 independent Chrome 150 connections |
| `validation.json` | wire gate result, produced by `tools/verify-wire-capture.py` |
| `source-evidence.json` | the 12 audited source files at the 150 release tag, produced by `tools/collect-profile-evidence.py` |

Reproduce the gate:

```sh
tools/verify-wire-capture.py --profile chrome_150 \
  --captures profiles/chrome-150/captures.json \
  --out profiles/chrome-150/validation.json

tools/collect-profile-evidence.py --version 150.0.7871.186 \
  --out profiles/chrome-150/source-evidence.json
```

## Wire gate

`wire_verified: true`.
3 connections from 3 distinct source ports.

Byte-identical on every connection: de-GREASEd cipher list, supported groups,
signature algorithms, HTTP/2 fingerprint and User-Agent. Different on every
connection: client random, session id, extension order, GREASE values, key share
and ECH payload.

The HTTP/2 fingerprint is
`1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p`,
matching the 152--155 captures. The `trust_anchors` extension is absent, which is
correct for this release: `kTLSTrustAnchorIDs` is `FEATURE_DISABLED_BY_DEFAULT`
until 152.

## Provenance

`captures.json` was produced by `tools/migrate-browserleaks-captures.py` from
`new/captures/chrome-150-validation/`, whose three records already carry their own
`tcpip.src_port` (three distinct values, so the connections are demonstrably
independent).

```sh
tools/migrate-browserleaks-captures.py --major 150 \
  --source new/captures/chrome-150-validation \
  --out profiles/chrome-150/captures.json
```
