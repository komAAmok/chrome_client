# chrome_149 profile

Evidence for the `chrome_149` profile, which is active in the table. Everything
here is regenerated by the commands below; none of it was hand-written.

## Files

| File | What it is |
| --- | --- |
| `captures.json` | 3 independent Chrome 149 connections |
| `validation.json` | wire gate result, produced by `tools/verify-wire-capture.py` |
| `raw/chrome-149-browserleaks-boundary-20260822/` | 3 session pcaps (primary evidence for the source ports `captures.json` reports), 3 `*.dumpcap.log` and 5 response records |
| `raw/chrome-149-h3-local/` | the H3 evidence this profile's status cites: 3 QUIC pcaps, 3 `*.keys` TLS key logs, 1 server straces, 3 body files, 2 validation JSON |
| `raw/chrome-149-validation/` | 4 endpoint response records |
| `source-evidence.json` | the 12 audited source files at the 149 release tag, produced by `tools/collect-profile-evidence.py` |

Reproduce the gate:

```sh
tools/verify-wire-capture.py --profile chrome_149 \
  --captures profiles/chrome-149/captures.json \
  --out profiles/chrome-149/validation.json

tools/collect-profile-evidence.py --version 149.0.7827.200 \
  --out profiles/chrome-149/source-evidence.json
```

## Wire gate

`wire_verified: true`.
3 connections from 3 distinct source ports.

Byte-identical on every connection: de-GREASEd cipher list, supported groups,
signature algorithms, HTTP/2 fingerprint and User-Agent. Different on every
connection: client random, session id, extension order, GREASE values, key share
and ECH payload.

The HTTP/2 fingerprint is
`1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p`,
matching the 152--155 captures. The `trust_anchors` extension is absent, which is
correct for this release: `kTLSTrustAnchorIDs` is `FEATURE_DISABLED_BY_DEFAULT`
until 152.

## Provenance

`captures.json` was produced by `tools/migrate-browserleaks-captures.py` from
`new/captures/chrome-149-validation/`, whose three records already carry their own
`tcpip.src_port` (three distinct values, so the connections are demonstrably
independent).

```sh
tools/migrate-browserleaks-captures.py --major 149 \
  --source profiles/chrome-149/raw/chrome-149-validation \
  --out profiles/chrome-149/captures.json
```

## Self-containment

`captures.json` is re-derivable from `raw/` alone, on a clean clone, with no
access to the pre-migration tree:

```sh
tools/migrate-browserleaks-captures.py --major 149 \
  --source profiles/chrome-149/raw/<the browserleaks or *-validation dir> \
  --out /tmp/regenerated.json
cmp profiles/chrome-149/captures.json /tmp/regenerated.json
```

The pcaps are committed because they are the primary evidence, not a
convenience copy: BrowserLeaks records only the *length* of each key share, so
the key material checked by the wire gate exists nowhere else. The `*.keys`
files are the per-session TLS traffic secrets for the captured H3 runs, which is
what makes those pcaps decryptable; they are evidence for an ephemeral session,
not a credential.

The `capture`/`key_log` fields inside the validation JSON still name the paths
those files had in the pre-migration tree. They are provenance records of where
each capture was taken, no in-repo tool resolves them, and rewriting them would
misreport the capture. The layout under `raw/` is the authoritative one.
